Summary to pass on

Infrastructure map

No account is shared, pooled or routed through a proxy. Each agent runs under its own person's login, in that person's own Linux user on the Ubuntu hub. Jobs the scheduler starts on its own use company API keys and the Claude Team credit pool.

Hill-climbing loop

  1. The brief names the metric, the smallest gain worth keeping, and three data sets. The tuning set guides the loop, the check set confirms each winner, and the audit set is used once at the end.
  2. The scheduler opens one git worktree per variant. Each free company seat, Claude or ChatGPT, writes one variant.
  3. Scoring runs in a throwaway sandbox with no secrets and no network. Test files sit outside the worktree and are checked by hash. The runner confirms every expected test ran.
  4. The winner and the current best re-run side by side across several seeds. The winner stays only if its gain beats the margin and no test breaks.
  5. The other company's model reviews the winning change, GPT for a Claude winner and Claude for a GPT winner. It looks for tricks that raise the score without improving the software.
  6. Only the scheduler writes the ledger. Winners rebase, re-score and merge one at a time, after a person reads the change.
